# Spec-Driven Workflow

## Overview

The spec-driven workflow ensures Claude knows exactly what to build — and only that — before touching a single file. It solves two core problems:

1. **Wrong output** — Claude misunderstands scope, builds too much or the wrong thing.
2. **Token waste** — generic prompts with no task-specific context, rework from misalignment.

---

## Full flow

```
developer describes task
        ↓
ai-kit spec new        → AI drafts structured spec file
        ↓
developer reviews      → edits scope, files, constraints
        ↓
ai-kit spec approve    → validates required sections, marks approved
        ↓
ai-kit spec start      → writes focused TASK.md at project root
        ↓
✦ Claude (TUI)         → Claude opens with TASK.md pre-loaded, implements tasks
        ↓
ai-kit spec review     → AI reviews implementation against spec
        ↓
(fix with Claude if needed)
        ↓
ai-kit spec close      → marks done, removes TASK.md, moves to done/
```

---

## File structure

```
.aikit-specs/
├── active/
│   └── SPEC-003-user-bio-field.md      # in-progress
├── draft/
│   └── SPEC-004-notifications.md       # drafted, not yet approved
├── done/
│   └── SPEC-001-auth-refresh-token.md
│   └── SPEC-002-product-pagination.md
├── .spec-counter                        # auto-incremented numeric ID
├── .active-spec                         # ID of the currently active spec
└── .spec-start-commit                   # git hash at the time of spec start
```

`TASK.md` is generated at the project root by `spec start` and removed by `spec close`.

---

## Spec file format

```markdown
# SPEC-003 — Add bio field to user model

## Status
draft | approved | in-progress | done

## What
One-sentence description of the deliverable.

## Out of scope
- List of things explicitly excluded

## Scope
- [ ] Task 1
- [ ] Task 2
- [x] Task 3 (completed)

## Files expected to change
- backend/app/models/user.py
- backend/app/routes/users.py
- backend/app/schemas/user.py (new)
```

**Rules:**
- `## What` must not be empty
- `## Scope` must have at least one `- [ ]` item
- `## Files expected to change` must list at least one file
- `## Out of scope` must be present (even if it says "none")

---

## Generated TASK.md

`ai-kit spec start` writes this to the project root so Claude reads it automatically on session start:

```markdown
<!-- AUTO-GENERATED by ai-kit spec start. Edit the spec, not this file. -->
# Current Task: SPEC-003

## Objective
Add an optional bio field to the user model.

## Tasks
- [ ] Add bio field to User model
- [ ] Create migration for bio column
- [ ] Include bio in GET /api/users/me response
- [ ] Allow PATCH /api/users/me to update bio

## Files to touch
- backend/app/models/user.py
- backend/app/routes/users.py
- backend/app/schemas/user.py  ← NEW

## Out of scope — do not touch
- Profile photo upload
- Content moderation

## When done
Run: ai-kit spec close SPEC-003
```

## Commands reference

### `ai-kit spec new [description]`

Generates a new spec file using AI.

**Flow:**
1. Auto-assigns next ID (reads `.aikit-specs/.spec-counter`)
2. Detects stack from existing `CLAUDE.md` or re-runs detect
3. Calls `claude -p` with stack context + description → fills spec template
4. Status set to `draft`

```
OK  Spec created: .aikit-specs/draft/SPEC-003-user-bio-field.md
... Review and edit the spec, then run: ai-kit spec approve SPEC-003
```

---

### `ai-kit spec approve <id>`

Validates and marks a spec as approved.

**Validations:**
- `## What` must be filled
- `## Scope` must have at least one task
- `## Files expected to change` must list at least one file
- `## Out of scope` must be present

```
OK  SPEC-003 approved
... Scope: 3 files, 1 new, 4 tasks
... Run: ai-kit spec start SPEC-003
```

---

### `ai-kit spec start <id>`

Activates a spec for the current session.

**Flow:**
1. Validates spec status is `approved`
2. Sets status to `in-progress`
3. Records current git commit in `.aikit-specs/.spec-start-commit`
4. Writes `.aikit-specs/.active-spec` pointing to spec ID
5. Generates `TASK.md` at project root

```
OK  SPEC-003 is now active
OK  TASK.md written at project root
... Claude Code will read TASK.md automatically on session start
... Auditor will log writes to files outside this spec's scope
... When done: ai-kit spec close SPEC-003
```

---

### `ai-kit spec update tick <N>`

Marks the Nth pending task as done in the spec file.

Tasks are counted only among unchecked `- [ ]` items (1-based). Automatically regenerates `TASK.md`.

```
OK  Task 2 ticked in SPEC-003
```

---

### `ai-kit spec review <id>`

Runs an AI review of the implementation.

**Flow:**
1. Reads the spec file (scope, expected files, tasks)
2. Runs `git diff` since the start commit
3. Sends spec + diff to `claude -p` for review
4. Reports: tasks completed, files changed vs scope, quality findings

---

### `ai-kit spec close <id>`

Closes the active spec.

**Flow:**
1. Runs a final review
2. Marks status as `done`, appends commit references
3. Moves file from `active/` to `done/`
4. Removes `TASK.md` from project root
5. Clears `.aikit-specs/.active-spec`

```
OK  SPEC-003 closed
OK  Linked to commits: abc1234 feat(user): add bio field
OK  Moved to .aikit-specs/done/SPEC-003-user-bio-field.md
OK  TASK.md removed
```

## TUI integration

The `ai-kit tui` command provides a visual interface for the full spec lifecycle:

| Button | Keyboard | Action |
|--------|----------|--------|
| Approve | `a` | Runs `spec approve` |
| Start | `s` | Runs `spec start` — generates TASK.md |
| ✦ Claude | `c` | Suspends TUI, opens Claude Code with the task pre-loaded; TUI resumes on exit |
| Review | — | Runs `spec review`, shows findings |
| Close | — | Runs `spec close` |

**Tab panels:**
- **Checklist** — live task progress with click-to-tick
- **Activity** — commits since start, changed files vs spec scope, audit findings
- **Spec** — full spec markdown
- **Log** — real-time output of running commands

## Auditor scope guard

When a spec is active, the auditor adds a scope check on every file write:

- Reads `## Files expected to change` from the active spec
- If the file being written is NOT in the list, logs a `LOW` finding:

```
[AUDITOR] LOW — SPEC-003 scope
File:    backend/app/models/other_model.py
Fix:     File is not in SPEC-003's scope. Intended?
         Update the spec or add: # ai-kit:ignore scope
```

Intentionally `LOW` (not blocking) — scope creep is sometimes intentional. The goal is awareness.
